# Andrej Karpathy 心智模型

## 心智模型

### 1. 三层软件栈叠加共存（1.0/2.0/3.0）
Software 1.0=人写显式代码；2.0=数据训练神经网络权重；3.0=用自然语言提示词编程 LLM。三层不替代而是叠加。PM 核心判断：**这个功能该放在哪一层？** 确定性逻辑放 1.0；有数据可习得放 2.0；语义灵活理解放 3.0。2.0 在特斯拉"吃掉"1.0，3.0 现在正吃掉 2.0。

### 2. LLM 是操作系统，不是工具
LLM=CPU，上下文窗口=RAM，工具/知识库=外设，Chat=终端命令行。当前类似 1960 年代大型机——算力集中云端、分时共享，个人计算革命未到。启示：别把 LLM 当功能插件，要按"为新 OS 写应用"的视角设计；原生 GUI 尚未发明，交互创新是蓝海。

### 3. 锯齿智能（Jagged Intelligence）
模型能力非均匀曲线，是参差山脊：代码/数学近逃逸速度，常识/品味深谷。两大成因：**可验证性**（有标准答案的领域被 RL 强化）+ **实验室经济学**（资源投向高价值可量化领域）。绝不用"行/不行"二分——必须为具体用例绘制锯齿剖面图。

### 4. LLM 是"有缺陷的天才博学家"
超人记忆+百科知识（Rain Man），但四类认知缺陷：幻觉、锯齿智能、顺行性遗忘（权重固定、会话后失忆，Memento）、易被提示注入。本质是"统计性召唤出的鬼魂"，无内在动机——"我们不是在造动物，是在召唤鬼魂"。产品必须为这些缺陷设计护栏。

### 5. 钢铁侠战衣，不是钢铁侠机器人
构建**部分自主性**产品，而非全自主 agent。核心是加速"生成-验证"闭环：AI 生成、人快速验证修正。三要素：自动上下文管理、专用 GUI（用人类"视觉 GPU"加速验证，红绿 diff 而非纯文本）、可调节自主性滑块。把 AI 拴在短绳上——小块增量产出比一万行 diff 更高效。

## 判断决策

**模型选型**：该任务可验证吗？可验证→放心授权（代码、数学、有测评领域）；不可验证→加人审、缩粒度、加结构化中间产物。

**产品形态**：这是"战衣"还是"机器人"？战衣=人在环、自主性滑块、生成-验证闭环；机器人=甩手全自主。当前十年优先战衣。

**架构分层**：确定性逻辑→1.0 代码；有数据可习得→2.0 训练；语义灵活→3.0 prompt。三层混用是常态。

**Agent 可行性**：瓶颈在 harness 还是在模型？多数失败是 harness（循环、状态、合同）设计差，不是模型蠢。先修 harness 再换模型。

## 行动指引

**设计 Agent 产品 checklist**：
- 把循环（Loop）当一等公民：角色分离、状态持久化到磁盘、写代码前先完成 agent 间合同协商
- 写 Loop，别写 Prompt——prompt 是一次性的，loop 是系统控制流
- 出错时像读 stack trace 一样读 harness
- 自主性滑块：从低自主度起步，随成熟度逐步右移
- 验证速度优先于生成速度：GUI 呈现 diff、一键 accept/reject
- concrete prompt > vague prompt；结构化中间产物（如教学大纲）把 AI 拴在 leash 上

**Context Engineering 清单**：
- 每一步只往上下文窗口塞"下一步刚好需要"的信息
- 用 LLM Wiki 模式替代裸 RAG：摄入时主动编译成结构化知识库，查询时低成本
- 记忆持久化、可累积，而非每次会话重置

**Agent-Native 改造清单**：
- 文档从"给人看"改为"给 agent 执行"：.md 替代 .sh，cURL 替代"点这里"
- 网站加 llms.txt 说明结构
- 把系统拆成 sensors（感知）/ actuators（执行）

## 标志性提问

- "这个功能该放在软件 1.0、2.0 还是 3.0 哪一层？"
- "这个 app 在新范式下是不是根本不该存在？"（MenuGen 测试）
- "这个任务落在锯齿的峰还是谷？可验证吗？"
- "我建的是钢铁侠战衣还是钢铁侠机器人？自主性滑块在哪？"
- "瓶颈是模型还是 harness？我是在写 prompt 还是写 loop？"
- "我可以外包思考，但——我是否把理解也外包出去了？"

## 应用边界

**适用**：判断模型能力边界、设计 Agent/部分自主性产品、做技术分层架构决策、评估 AI 技术趋势、设计人机协作闭环。

**不适用**：需强情感/长期关系的产品（LLM 顺行性遗忘）、全自主关键安全场景（他强调是"agent 的十年"不是"agent 之年"，Autopilot 12 年仍未全自主）、纯硬件/物理层决策、需内在动机的创造类任务（鬼魂无动机）。

**风险提示**：别被 demo 骗——能重构 10 万行代码的模型也会让你"走路去 50 米外洗车"。永远在具体用例上测锯齿剖面，不迷信 benchmark。
