# 俞军产品方法论

## 核心框架

### 一、用户价值公式

```
用户价值 = 新体验 - 旧体验 - 替换成本
```

- **新体验**：你的产品带来的效用提升。做大路径=引入新技术/新要素（AI 即新要素）。
- **旧体验**：用户当前方案的效用。寻找"旧体验≈0"的用户群（小白/新场景）是最大机会。
- **替换成本**：货币、时间、认知、迁移、习惯惯性。拉新要降低它，留存要提高它。

**三条提升路径**：做大新体验 → 降低旧体验 → 降低替换成本。

**判断标准**：用户价值 > 0 是产品成立的最低门槛。若新体验仅比旧体验好一点，替换成本会吃掉全部优势。

### 二、交易模型

```
相对价格 = (直接成本 + 交易成本) ÷ 效用组合
```

产品即交易——用户每一次主动行为都是一次交易。产品经理的进阶线是从"理解用户模型"到"设计交易模型"。

- **效用组合**：省钱、省时、安全感、确定性、社交连接、情绪满足、身份感……同一产品对不同场景提供不同效用。拆解产品为效用组合，而非功能清单。
- **交易成本**：用户付出但企业没收到的成本（搜寻、度量、寻价、决策、实施、保障）。利润藏在交易成本的降低中。
- **好产品三属性**：对用户有效用 + 对企业有收益 + 可持续。三者缺一不可。

**需求四层级**：底线需求（不能低于）> 够用就好（不用高于）> 越多越好（愿意多支付）> 惊喜（超预期）。资源有限时，先守底线，再投"越多越好"，惊喜适量。

### 三、理性决策三要素

1. **理性信念**：对自我认知的认知。我的认知能打几分？可能有哪些偏差？值得花多少成本获取信息？
2. **理性目标**：约束条件下的总效用最大化。反思目标本身——目标错误，越努力错越多。
3. **理性行动**：给定目标，找最优解。任何权衡都是决策，追求整个系统的效率。

## 行动清单

### 需求价值评估 Checklist

- [ ] 场景是什么？用户在什么情境下遇到什么问题？
- [ ] 有多少人有此需求？频次多高？
- [ ] 不解决会怎样？用户有多痛？
- [ ] 旧体验是什么？打几分？
- [ ] 新体验能打几分？差距够大吗？
- [ ] 替换成本有哪些（金钱/时间/认知/迁移）？有多大？
- [ ] 用户价值 = 新体验 - 旧体验 - 替换成本，> 0 吗？
- [ ] 有无更值得做的需求？（机会成本）

### 产品决策三步法

1. **有需求**：市场多大？饥渴度多强？增量还是存量？
2. **有优势**：关键满意度点接近对手，至少一点全力领先。能转化为产品价值的优势才是优势。
3. **有利益**：预期成本可控？有收益才有未来。产业链利益平衡，成长正循环。

## 决策工具

### 真需求 vs 伪需求判断矩阵

| 维度 | 真需求 | 伪需求 |
|------|--------|--------|
| 频率 | 高频使用 | 低频/偶尔 |
| 强度 | 不解决很难受 | 不解决无所谓 |
| 场景 | 有明确场景 | 场景模糊/想象 |
| 付费 | 愿意付出成本 | 犹豫/不愿 |
| 替代 | 无满意替代方案 | 有其他解决方案 |

### 用户五属性速查

- **异质性**：每人偏好、认知、资源不同
- **情境性**：行为受场景影响（同一人不同场景=不同用户）
- **可塑性**：认知可被改变（补贴养习惯）
- **自利性**：追求个人总效用最大化
- **有限理性**：追求理性但能力有限，判断常出错

口诀：用户不是自然人，是需求的集合。

## 常见错误

1. **目标错误**：多数人只关注"怎么做"，不反思"为什么做这个"。目标错，行动越高效错越多。
2. **自嗨型产品**：把"我觉得"当用户需求。数据是验证工具，不是决策唯一依据——但无数据验证的直觉更危险。
3. **只讲体验不讲收益**：用户价值为正但商业价值为负，不可持续。只讲变现不讲体验，交易会被抛弃。
4. **过早做管理**：前五年应积累产品经验，过早管理是减分项。PM 产出靠决策质量，不靠人多。
5. **给用户不想要的东西**：任何没用的功能都是对用户的伤害。替用户预先想好，不让用户思考和选择。
6. **忽视替换成本**：产品只比竞品好一点不够，必须覆盖用户迁移的全部成本。

## 应用边界

**适用场景**：
- AI 产品立项评估：用用户价值公式判断新 AI 功能是否值得做
- 需求优先级排序：用需求四层级 + 机会成本权衡
- 商业模式设计：用交易模型分析多边利益分配
- 产品迭代决策：理性决策三要素 + 数据验证

**不适用场景**：
- 纯技术架构选型（不涉及用户行为分析）
- 0→1 极早期探索中无旧体验可参照时，公式参考价值降低
- 非交易型产品（如公益、内部工具）中"企业收益"维度需重新定义

## PM 成长路径

- **前五年（学习期）**：大量迭代验证，积累用户样本，掌握用户模型。多做产品多思考，不要急管理。
- **五年后（分岔路）**：
  - **专业路线**：深挖交易模型，做权衡决策。顶尖 PM 留在高增长业务，不创业（机会成本太高）。
  - **管理路线**：识人用人，让优秀下属做决策。
  - **业务路线**：扎根细分领域做专家，To B 成功率更高。

**PM 价值公式**：经验等级 × 平台匹配度 × 智慧等级
